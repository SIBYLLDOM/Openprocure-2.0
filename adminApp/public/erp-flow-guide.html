The spine

One customer, start to finish

This is the single chain that ties all three modules together. Everything else on this page is detail hanging off these eight steps — if the demo only has time for one thing, do this.

queued waiting on a decision active in progress done approved / completed stopped rejected / cancelled / failed

  1. Customer Master — the account is opened

    New hospital/lab record on the User table (userType: customer). The Sales Profile card on the customer's detail view is where gstNumber, creditLimit and creditTerms (Net 15/30/45/60/Advance) actually live — this is the only place GST number is stored against a customer.

    businessStatus: Active

  2. Quotation — sent, then Accepted or Rejected

    Built from a per-line-item editor: Product, Qty, Unit Price, Discount %, and a GST % field defaulted to 18 and typed per line — not pulled from the customer's own GSTIN, and there is no CGST/SGST/IGST split anywhere in Sales (that split only appears later, inside Finance). A quotation is born Pending — there's no Draft or Sent status in this system.

    Pending Accepted Rejected

  3. Sales Order — a manual conversion, not automatic

    Accepting a quotation only unlocks a "Convert to Sales Order" button — someone still has to click it. The order then walks its own pipeline.

    Pending Confirmed Processing Packed Dispatched Delivered Cancelled
    → moves to Confirmed → reserveStockForOrder() pulls stock from available into reserved

  4. Invoice — Finance posts itself, silently

    An order can be invoiced once it's Confirmed or further along. Clicking Generate creates the invoice and — in the exact same transaction — writes a balanced journal entry to the General Ledger. No one on the Finance side does anything.

    → postInvoiceToLedger() — Debit Accounts Receivable, Credit Sales Revenue + GST Payable

  5. Dispatch — stock physically leaves on Delivered

    A dispatch can't exist until its invoice does. It then walks a strictly linear chain — no skipping, no reverse.

    Packed Shipped In Transit Delivered
    → reaches Delivered → releaseStockForDispatch(), order snaps to Delivered too

  6. Sales Return (optional) — restock, then a credit note

    Started against an invoice, capped at invoiced quantity per line.

    Requested Approved Rejected Completed
    → Approved → restockFromReturn(); issuing the Credit Note → postCreditNoteToLedger() (Debit Sales Returns / Credit AR)

  7. Manufacturing — refills what Sales just sold

    A raw-material Batch arrives and is QC'd, an Approved Bill of Materials defines the recipe, and a Work Order turns raw material into finished-goods stock — the exact stock that step 3 reserves and step 5 releases.

    → Work Order Mark Complete → new finished-goods Batch created + postJournalEntry() (Debit Manufacturing Expense / Credit Inventory Asset)

  8. The catch — only 3 products are actually wired end-to-end

    The bridge between a Sales catalog Product and a real warehouse-tracked ItemMaster row is a single field, Product.itemMasterId. Only three products have it set. Every other product's order confirmation is a silent no-op on inventory — real, but invisible.

    5 Part Hematology Analyzer AutoQuant 400 Biochemistry Analyzer CliniQuant Micro

    Demo tip: run the live stock-movement chain using one of these three products, or the reservation/release steps will do nothing visible.

Customer Master
Where the account, the GST number, and the credit terms live.
Fields: Hospital/Lab Name, Contact Name, Email/Password, Phone, Onboarded By (Sales / Tender), City/State/Pincode/Address, and a Sales Profile block: gstNumber, creditTerms, creditLimit (₹).
  1. Open a customer row → the Sales Profile card shows GST Number, Credit Terms, Credit Limit.
  2. Edit any of the three → Save writes straight back to the customer record.
NOTE — the standalone "New Customer" creation modal exists in the code but has no visible open-button wired on this page currently. Don't go hunting for it live.
Quotations
Line items, GST %, Accept/Reject, then convert.
PendingAcceptedRejected
  1. New Quotation → pick Customer, Expiry Date, Notes, add line items (Product / Qty / Unit Price / Disc % / GST %, default 18) → Create Quotation.

Finance

The Ledger that writes itself

The headline feature: nothing above posts to Finance by hand. Every hook below runs inside the same database transaction as the Sales action that triggered it.

General Ledger
Auto-posted entries, plus manual Journal Entries.
DraftPostedReversed
  1. Open this page right after generating a Sales invoice — a Sales-type entry, already Posted, is already sitting there.
  2. New Journal Entry → Entry Date, Reference, Description, a repeatable Debit/Credit line table against the Chart of Accounts. A live strip shows Balanced / Unbalanced.
  3. Post Entry is disabled until balanced — one click both creates and posts it.
  4. Open any Posted entry → Reverse Entry creates a brand-new voucher with every line flipped, and marks the original Reversed.
Accounts Payable
Vendors, Bills, Payments.
PendingPartialPaid

  2. New Vendor → Name, GSTIN, Contact, State, Payment Terms.
  3. New Bill → Vendor, Bill Number, Invoice/Due Date, Taxable Value, GST Rate → posts Purchase Expense + GST Input Credit automatically.
  4. Record Payment per bill → Amount, Mode, Reference No.

Accounts Receivable

Master stock view + Adjust action.

Batch / Lot Tracking

Bill of Materials
The recipe — must be Approved before a Work Order can use it.
DraftPending ApprovalApprovedRevised
  1. New BOM → Parent Product + repeatable component lines (item, qty, unit, cost) → starts Draft.
  2. Draft → Submit for Approval → Pending Approval → Approve or Reject (Reject bounces back to Draft).
  3. Approved → Create New Version clones it as a new Draft v2, marks the old one Revised.
Production Planning (Work Orders)
Start reserves the BOM; Complete produces stock and posts to Finance.
ScheduledIn ProgressCompletedDelayedOn HoldCancelled
  1. New Work Order → Product, an Approved BOM, Factory, Production Line, Warehouse, Quantity, dates, Priority, Assigned Team.
  2. Start Production → reserves every BOM component's required quantity from available stock, order moves to In Progress.
  3. Mark Complete → consumes the reserved materials, adds the produced quantity to finished-goods stock, creates a brand-new Batch (Passed) tagged to this Work Order, and posts the manufacturing cost to Finance.
FIRES → Mark Complete → Debit Manufacturing Expense / Credit Inventory Asset. Toast literally reads: "Production completed — finished goods stocked, manufacturing cost posted to Finance."

Read before you present

Don't click these live

Real gaps in the current build, found while tracing the code — knowing them ahead of time is cheaper than discovering them mid-sentence in front of the team.

AVOID

Quotations' Email button downloads a PDF and opens a Gmail compose draft — it does not send an email itself. Say "download and compose," not "send."

AVOID

Compliance Pack's Download button has no click handler at all. "Generate" produces an audit-trail record, not a file — don't promise a download.

AVOID

Bank Reconciliation's Import and Manual Match exist on the backend but have no button in the UI. Only Start, Auto Match, and Complete are real click paths.

AVOID

Budgeting has no Draft → Approve step. A budget is Active the second it's created — there's nothing to approve.

AVOID

Accounts Payable's "Overdue" filter will return nothing — no code path ever sets that status. Use the Aging column instead.

AVOID

Stock Transfers created through the current form are already completed the instant you submit — their Approve/Reject buttons are dormant. Don't demo "pending transfer approval."

AVOID

Fixed Assets' Run Depreciation is once per calendar month, per asset — a second click in the same month returns an error.

AVOID

Customer Master's "New Customer" modal exists in code with no visible open-button on the page yet — edit an existing customer's Sales Profile instead.
